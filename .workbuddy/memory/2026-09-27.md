## 1. 弦鸣引擎「按下去完全没声」——真 bug，探针抓到的

`probe-synth.mjs` 新增的「七引擎逐个离线渲染」段当场抛
`InvalidStateError: cannot call start more than once`（**只有 string 中招**）。

根因：`trigger()` 里两条起振清单**共用同一个数组** `extraStarts` ——
通用循环 start 一次、弦鸣专属分支又 start 一次。异常逃出 `trigger()`
→ `noteOn()` 后半段（排自动释放 + 注册声部）整段跳过 → 该音色一个音都不出。

修法（按「一份清单只背一种语义」拆开）：

- `triggerStarts` —— `trigger` 负责 start（白噪声叠加支路、噪声引擎主源）。
- `extraStarts` —— **只登记回收**：粒子 grain、噪声换色的新源、弦鸣脉冲。
- `dispose()` 两个清单都遍历。
- `trigger` 的循环改遍历 `triggerStarts`。

⚠️ 单测当时 29 条全绿也没照出来：假 AudioContext 的 `MockSource.start()` 是**幂等**的。

## 3. ⛔ 探针写进了「影子 store」——`roll-verify.mjs` 报「找不到卷帘 canvas」

看着像「卷帘挂了」，实际是**探针工具链的假红**：

- App 用的是 `…/src/model/store.ts?t=1790476600152`（Vite HMR / 依赖重优化加的缓存击穿），
  探针 `import('/src/model/store.ts')` 拿到的是**另一个模块实例 → 另一个 zustand store**。
- 探针 `setState` 写进影子 store：它自己读回来「明明有」，页面一无所知 →
  显示空状态（`录骨架 · 卷帘修` + `钢琴卷帘还空着`）。
- **只在「dev server 跑过一轮 HMR / 重优化」时出现**，冷启动一切正常 →
  探针的可信度取决于服务器新鲜度，而这件事没人会记得。

修法（新文件 `scripts/_app-import.mjs`，两个卷帘探针共用）：

- `APP_IMPORT_BOOTSTRAP` → `window.__appImport(path)`：按 `performance` 里 App
  **真正请求过**的那条 URL（**取最后一次**）去 import；找不到就**抛**，不许退回裸路径。
- `storeIdentityCheckSource()`：用 store 自己的 `setKeyCount` 改一个数，看侧栏
  `N 键 · M 素材` 有没有跟着变 → 证明拿到的是**同一个实例**。两个探针都在注入任何
  状态**之前**先跑它，不过就当场抛。
- 已同步修正 `REF-frontend.md §8` 里那条「造数据走 IndexedDB + 刷新」的旧绕法
  （原先写成「这是没法避免的」，现在是确定性解法）。详见新写的 `REF-frontend.md §5.3`。
