## 1. 弦鸣引擎「按下去完全没声」——真 bug，探针抓到的

`probe-synth.mjs` 新增的「七引擎逐个离线渲染」段当场抛
`InvalidStateError: cannot call start more than once`（**只有 string 中招**）。

根因：`trigger()` 里两条起振清单**共用同一个数组** `extraStarts` ——
通用循环 start 一次、弦鸣专属分支又 start 一次。异常逃出 `trigger()`
→ `noteOn()` 后半段（排自动释放 + 注册声部）整段跳过 → 该音色一个音都不出。

修法（按「一份清单只背一种语义」拆开）：

- `triggerStarts` —— `trigger` 负责 start（白噪声叠加支路、噪声引擎主源）。
- `extraStarts` —— **只登记回收**：粒子 grain、噪声换色的新源、弦鸣脉冲。
- `dispose()` 两个清单都遍历。
- `trigger` 的循环改遍历 `triggerStarts`。

⚠️ 单测当时 29 条全绿也没照出来：假 AudioContext 的 `MockSource.start()` 是**幂等**的。

# 手机端「电子音一卡一卡」定位（当日追加）

用户报：桌面正常，**手机端电子音有「一卡一卡」的感觉**。

## 新增探针 `scripts/probe-synth-mobile.mjs`

CDP + 手机视口（844×390 @3x）+ **CPU 节流 1/4/6/8x**。为什么必须新写：
vitest 没有 Web Audio；`probe-synth.mjs` 用 `OfflineAudioContext` —— **离线渲染不跑定时器、
也不存在「主线程被占住」**，它量的是出声没有、干不干净，量不到卡顿。

三个决定性量法（写进探针注释）：
① **包裹 `window.setInterval`** → 拿到引擎两个定时器回调的 count/总耗时/最大耗时；
② **包裹 `AudioContext.prototype.create*`** → 每次按键到底造多少节点；
③ **帧间隔只在演奏窗口内采样** → 否则最大值被模块加载污染成 1~3 秒（第一版就栽了）。

## 实测（6x ≈ 中端手机，一帧 16.7ms）

| 动作 | 1x 桌面 | 6x | 8x | 造节点 |
|---|---|---|---|---|
| 按一个键 | 2.1ms | 11.1ms | 17.3ms | **20.06 个** |
| 叠音 6 个 | 2.0ms | 11.1ms | 16.7/20.2ms | 20 个 |
| 首次进入电子音发声 | 81ms | **269ms** | **462ms** | 52 个 |
| 换音色 `loadSynthPatch` | 18–29ms | 157–242ms | 229–330ms | **0 个** |

⭐ **`setPatch` 分摊（本次最硬的一条）**：

| 倍率 | 全等 patch | 只改 1 个参数 | 拖动 1 个参数 | 拖动同一值 |
|---|---|---|---|---|
| 1x | 24.7ms | 25ms | 0.6ms | 0ms |
| 6x | **166.9ms** | 156.8ms | 1.5ms | 0.5ms |
| 8x | **275.2ms** | 208.3ms | 1.4ms | 2.2ms |

**「一个值都没变的全等 patch」也要 167ms** → **`setPatch` 的成本只与「patch 有多少键」有关，
与「改了多少」无关**：它对全部 117 个键**无条件**调 `writeParam`（无早退）。
而 `applyParam`（拖动路径）第一行就 `if (this.patch[name] === v) return;` → 1.5ms。

**推论（就是用户听到的那个卡）**：拖旋钮时每次移动走 `applyParam` = 1.5ms（不卡），
但松手 **120ms 尾随落库 → `store.setSynthPatch` → `engine.setPatch` = 167ms 冻结**；
触屏拖动常停停走走，防抖被反复触发 → **反复 167ms 冻结 = 「一卡一卡」**。
点预设 / 换引擎 / 重置走同一条路（0 个节点，纯 CPU）。

## 排除掉的三条（省得改错地方）

- ❌ **声部泄漏** —— 四档全绿：`created=29=disposed`、`live=0 dying=0`、排空 0ms。
- ❌ **250ms 清扫器** —— 最大 4.3ms（8x 下 5.8ms）。
- ❌ **16ms 调制节拍** —— **一次都没跑**（0 次）：classic + 无调制矩阵时它按设计自己停表。

## 另一条实测：`wavetable` 是全七个引擎里最重的

换完引擎后的第一个音：1x 4.2ms / 6x **32ms** / 8x **41.9ms**（要建 `PeriodicWave` + 双振荡器）。
其余引擎在 6x 下 7–23ms。

## 待定（尚未动手）

修法优先级：① `setPatch` 去重（零音色风险、纯性能，可用指标验收）；② 声部池化 / 降 20 节点数；

②改了发声路径 → 必须回到「耳朵定」那条规矩。

> 期望: 按下多个按键的时候 同时都可以播放动画 且 可以支持长按

（「变蓝」= `flame400` 实为 `#409CFF`。名字叫 flame，颜色是蓝。）

## B. 根因：**状态粒度错了**，不是少了个判断

`src/hooks/useKeyAnimations.ts` 旧版：

    lastPress: { keyIndex, pressed } | null      ← 全局单槽
    pressTimerRef = setTimeout(→ null, 260)      ← 到点强制「松手」

- 多键同按 → 后按的键占住槽位，先按的键 `externalPress` 变 undefined，
  MemeKey 里 `else setPressed(false)` 把它画回未按下（手指还按着）
- 长按 → 260ms 到点槽位清空 → 动画自己结束

⇨ **旧版根本没有「按住」这个状态，只有「最近一次触发后的 260ms」。**
另一个隐藏项：`lastFlash` 也是单槽 → 300ms 内按两个键，前一个的闪灯被掐掉。

## C. 改法（五处）

1. **`src/hooks/key-anim-state.ts`（新）** —— 纯状态内核（无 React / 无 DOM，node 里可测）：
   `pressKeyIn` / `releaseKeyFrom`（集合）、`setFlashIn` / `clearFlashIn`（映射 + token）、`FLASH_MS`。
   - 无变化时**返回入参本身** → React 靠 `Object.is` 跳过重渲染（36 个键的重复点击路径）
   - 闪灯带 `token` → 200ms 内连点两次时，**第一次的定时器不许掐掉第二次的闪灯**
2. **`useKeyAnimations` 重写**：`pressedKeys: ReadonlySet` + `flashes: ReadonlyMap`；
   `pressKey`/`releaseKey` **事件驱动、零定时器**；每键一个闪灯定时器；
   `window.blur` / `visibilitychange(hidden)` → `clearPressed()`。
   ⛔ **松开事件是会丢的**：按住时 Alt+Tab 走掉，那一下 keyup 落在别的窗口 →
   键位永远卡在按下态。兜底必须有。
3. **`shortcuts.ts` 补 `registerKeyUp`**（文件头规则 #4 早就承诺「后续加」）。⛔ **keydown 与 keyup
   的语义相反**，照抄必错：**不短路**（keyup 要派发给所有匹配者）、`guardInput` 默认 **false**、
   **不设 `when`**、`keys` 可省略 = 收全部。顺带修掉 StudioPage 的裸
   `window.addEventListener('keyup')`（违反规则 #4）。
4. **`MemeKey`**：`externalPress` → `externalHeld`；显示值 `showPressed = pressed || externalHeld`
   （两个来源**取或**，谁也不能清掉对方）；删掉那个 `else setPressed(false)` 的 effect。
5. **两个消费端**（StagePage / StudioPage）：动画从共享的 `playNote` / `wrappedTapKey`
   移回**各自的输入路径**。⛔ 规矩：**谁发起的输入，谁负责这一路的动画**。
   指针路径归 MemeKey 本地态（各实例一份 → 多指同按免费成立），键盘路径归页面。

## D. ⚠️ 自己造的一个坑（靠探针抓出来）

键盘路径写成 `const result = playNote(i); if (result === null) return; pressKey(i);`。
而 `playNote` 在 **`handlePress` 返回 null（KeyMachine 未就绪）** 时也返回 null ——
那是「此刻出不了声」，不是「这个键不可演奏」→ 按了绑定键**毫无视觉反馈**。
修：`handlePress(i) ?? { triggered: false, slotIndex: null }`，`null` 只保留「不可演奏」一种含义。

**为什么单测测不到**：指针路径不受影响 —— MemeKey 的 `fire()` 在调 `onPress` **之前**就设好了
本地按下态。所以这个坑只在键盘路径显形（探针里表现为「指针全绿、键盘全红」）。

用户原话：
> 关于弹奏时候声音性能问题 / 还是需要优化 / 它还是会在某些情况下导致无声 /

## A. 瓶颈：YIN 每次都重算，而它占了 78%

`hajimi_tx_run` mode=1 里 `track_pitch`（YIN）+ `detect_marks` **只依赖源素材**，
与 pitch/time 无关，却每次调用都从头算。项目自己在 `wasm/src/yin_core.rs:6-8`
就写着「实测占 mode=1 总耗时的 ~78%」，但从没人跨调用复用。

首次实测（`scripts/_perf-psola.mjs`，5s 素材）：PSOLA 2124ms / SOLA 368ms
→ YIN 净成本 **1756ms（83%）**。

## B. Rust 两处改动（`wasm/src/`）

1. **`psola.rs` 新增「分析结果复用」**：`analysis_for(x, sr)` 按**内容指纹**缓存
   `(Rc<Vec<PitchFrame>>, Rc<Vec<Mark>>, voiced)`，`ANALYSIS_CACHE_CAP = 48`。
   - 指纹必须覆盖**全部样点**（抽哈希会让两段尾部不同的素材撞键 → 复用别人的音高轨迹，
     输出错得莫名其妙且不报错）。守卫专门覆盖这条。
   - `voiced` **必须一起缓存**：它填 `LAST_VOICED`，现算的话命中那一次会报 0 →
     每次重复按键都被判「静默空转」→ 降级到 SOLA，症状伪装成「第二次按同一个键音色变了」。
   - 用两个 `Rc` 而不是借用：调用方持有期间缓存条目可能被换出。
2. **`yin_core.rs` 差分+CMND+阈值搜索交错，命中即止**。
   定理：CMND 的归一化分母 `running = Σ_{k≤tau} d[k]` 只累积到当前 tau，
   所以 `cmnd[tau]` 只取决于 `d[1..=tau]`；阈值搜索本来就是找**第一个**过阈的 tau
   → 后面的 d 全是白算。**逐位相同，不是近似**。
   用 `macro_rules!` 而不是闭包（闭包会同时可变借用 diff/cmnd 与 running，借用检查过不去）。

**⭐ 逐样本实测（`scripts/_probe-psola-cache.mjs` 同进程 A/B，逐样本 bit-exact）**：

| 场景 | 改前 | 改后 | |
|---|---|---|---|
| ① 顺序 12 键 | 2785ms | **777ms** | 3.6× |
| ② 再按一遍 | 2837ms | **40ms** | 70.9× |
| ③ 同键连按 20 | 6941ms | **111ms** | 62.6× |
| ④ 两键来回 20 | 6559ms | **96ms** | 68.0× |

改前每次按键恒 ~300ms；改后 `382,148,201,9,6,4,5,4,4,7,5,4` —— 只有三个素材各自首次付分析。

## C. JS 四处改动（`src/`）

1. **缓存额度「条数 → 字节」**：`RUSH_CACHE_BUDGET_BYTES = 8MB`，
   `evictToBudget(m, bytes, bytesOf)` 抽成纯函数供三处共用
   （`rush/transform.ts`、`rush/autotune.ts`、`sample-player.ts` 的外部分支）。
   - 一条 = `length × channels × 4`，跨度两个数量级：0.15~0.45s 切片 58~173KB，
     3 分钟人声 66MB。
   - 旧固定「每源 8 条」对短素材太紧（12 键工作集装不下 → LRU 抖动 →
     **每次按键都重算**），对长素材太松（8 × 66MB = 530MB 爆内存）。
   - ⛔ **至少保留一条**（哪怕单条 66MB 超预算）。
2. **`effects.ts::peekMasterChain()`**：`KeyMachine.destination` 是每次 trigger
   都求值的 getter，而它调的 `getMasterChain(project.effects)` 语义是「传了 settings
   就 apply」→ **每按一个键都把整条效果链参数重排一遍**（含一条新的 50ms 输出增益斜坡）。
3. **`prewarmKeyTransforms` 把变换成本挪到按键之前**
   （`model/buffer-cache-service.ts`）+ 接进 `prewarmReady` 指示灯。
4. **删掉 `key-machine.ts` 里每次按键的 `console.log('[trigger]', {...})`** ——

## D. ⛔ 三个真 bug（都是探针逼出来的，不是推出来的）

1. **`prewarmKeyTransforms` 在 WASM 还没加载完时直接 return 空报告**，
   调用方把它当「预热完成」→ 指示灯写「就绪」而**一条变换都没算**。
   探针实测：12 条全部没算，补算一次 237~279ms，头几个键按下耗时 45~71ms + 77ms 长任务。
   **修**：`await ensureRushLoaded()` 再判 `isRushReady()`。
   ⚠️ 注意 `warmed` 计数**包含缓存命中**（`transformBuffer` 命中直接返回），
   所以「warmed === 0」根本不是判据 —— 唯一可信的是 **wasm 调用次数**。
2. **`prewarmReady` 从不复位**：effect 依赖 `[hydrated, blobs]`，每次新增素材都会重跑，
   但旧写法只在末尾 `setPrewarmReady(true)` → 新一轮预热正在阻塞主线程时灯还写着
   「就绪」。**修**：effect 开头 `setPrewarmReady(false)`。
3. **`ensureAudioStarted()` 无条件调 `resume()`**（注释却写着「已解锁时为 no-op」）——
   每次按键都造一个 promise + 挂 `.catch` + 排一个微任务。
   **修**：`if (c.state !== 'running')`。

## E. ⭐ 新探针 `scripts/probe-play-perf.mjs`（14 项，全绿）+ 三条通用坑

埋点（`Page.addScriptToEvaluateOnNewDocument`，**必须先于导航**）：
`AudioContext.prototype.createBufferSource().start()` 计数 / `pointerdown` 捕获相打点 /
`longtask` 观测 / **wasm `hajimi_tx_run` 调用计数**。

结果：弹 12 键 **12/12 发声**，同步耗时 p95 **4.3ms**（热态 0.5ms），**0 长任务**，
**0 次 wasm 重算**；连击 20 次 20/20 发声、0 长任务。

⛔ **三条坑（都踩了，且都伪装成产品 bug）**：

1. **探针给 `instance.exports.hajimi_tx_run` 赋值失败，计数恒 0 → 13 项假绿**。
   WebAssembly 的 exports 属性**只读**，ESM 是严格模式 → 赋值抛 TypeError 被 catch 吞掉。
   **修**：复制整个 exports 换一层包装，再把 `instance` 换成持有新 exports 的普通对象。
   **⭐ 并加「埋点自检」**：用必定未算过的音高比强制造一次变换，计数不动就直接红
   —— 否则所有「0 次」断言都是永远为真的谎言。
2. **目标键必须取自页面上真实渲染的 `data-key-index`**，不能自己写 0..11。
   关闭半音键时键区是**白键布局**（0,2,4,5,7,9,11,12,14,16,17,19…），照 0..11 播种
   会有 5 个键真没装东西 —— 而它看起来**和用户报的「无声」一模一样**。
3. **按下与 start 必须按 keyIndex 配对，不能按下标顺序配**。只要一个键没发声，
   后面全体错位，读出来是一串看着很合理的 87ms（实际是错位垃圾）。
   另外「预热/就绪复现」不能靠轮询运气：得**让演奏台重新挂载**（导航到别的页再回来）
   —— 只换 Take 不动 `blobs` 不会让预热 effect 重跑，探针会把自己没触发 effect
   说成「指示灯说谎」。

**⭐ 定向变异已做**（两处，都红过再修回）：

  `cache_distinguishes_sources_differing_only_in_the_tail` 红。
