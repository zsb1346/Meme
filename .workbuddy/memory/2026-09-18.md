### PitchNet 算法要点（供后续参考）
- 范式是「分析 → 编辑 → 重合成」，不是单纯的 DSP 变调器：
  - F0 检测：RMVPE / FCPE（ONNX 神经，GPU）
  - 音符切分：GAME（D3PM 扩散）+ dur2bd / bd2dur
  - 重合成：`Vocoder`（PC-NSF-HiFiGAN，默认）或 `PsolaSynthesizer`（纯时域，零 FFT）
  - Voiced-Only Blend：voiced 用合成、长 unvoiced（≥24 帧）直通原声
  - 可选 `FormantShifter`（倒谱包络反移）
- PSOLA 关键设计（`Source/Audio/Synthesis/PsolaSynthesizer.cpp`）：
  - pitch marks 用归一化互相关精修（非峰值拾取）
  - 颗粒 = 2 个「分析周期」Hann 窗，窗零点压在相邻脉冲上 → 形体内在保留、ratio=1 逐样本还原
  - 按「窗口和 Σw」归一 + floor 0.3 + 局部 RMS 增益匹配
  - `DspSynthesisRequest` 用统一时域映射 `sourceFrame` 支持任意重定时
  - onset anchor（`needsAnchor`）消除段落接缝的梳状滤波
- 重采样用 r8brain CDSPResampler24（过渡带 2.5%）

### 定位到的缺陷（用户反馈「变调/拉伸像放屁」）
1. `psola.rs:916-941, 974-986` blend mask 建在**源时间轴**（`i*hop`），但 out_len 是输出时间轴 → τ≠1 时 mask 错位；τ>1 时输出后半段 mask 恒 0 → 退化为 `lerp(src, i/time)` 裸线性插值拉伸
2. 帧栅格错位：`track_pitch` 帧中心 = `WIN/2 + i*HOP`（1024+480i），但 `f0_at` / `f0_at_sample` / `build_marks` / `split_voiced` 都按 `i*HOP` 索引 → ~21ms（1024 样本）系统性偏移，且 `psola.rs:321` 的 `sample_pos` 是死代码
3. `psola.rs:654-655` 用 Σw² 归一（PitchNet 用 Σw），却沿用同一个 `ENVELOPE_FLOOR = 0.3` → 降调时接缝处被清零，叠加 `MAX_GAIN 4.0` 变成 f0 速率颤音
4. 缺 onset anchor（PitchNet `needsAnchor`）
5. `stretch.rs:28` 重采样仅 16 抽头 Hann-sinc（vs r8brain）
6. `stretch.rs:245` SOLA：±384 / step2 搜索 + step4 相关 + 512 线性交叉淡化
7. `psola.rs:20-21` YIN 硬限 70–500Hz；清浊用「3 连帧」启发式（PitchNet 用神经检测 + GAME）
8. `lib.rs:414` mode1 pitch clamp 0.5–2.0（±12 半音），mode2 无 clamp，行为不一致

## 已知极限：ratio → 2.0 的相干抵消（未解决，已写进 psola 模块头）

实测（48000Hz，200Hz 源，`hajimi_tx_run` mode=1，中段 RMS 比）：
- 逐样本相位积分的谐波堆（严格周期）：r≤1.682 → 0.997；r=1.888 → 0.221；r=2.000 → **0.000**；r=2.107 → 0.096
- 单频正弦 `make_sine`，r=2.0 → **0.0001**
- `make_vowel`（逐谐波 f32 相位，高次谐波已越过 f32 精度）r=2.0 → **1.0001**

最后两行是**同一内核、同一名义内容差四个数量级** —— 所以这不是固定比例的电平损失，而是
**相干性**现象：信号越严格周期、能量在周期内越分散就越容易整体反相抵消；真实录音有抖动/
噪声/声门脉冲就会削弱它。结论只能是「±10 半音以上属于必须单独实测的区间」，不要外推。

**这是 TD-PSOLA 几何固有**，PitchNet 同款 `clamp(0.25, 4.0)` 也只能补 12dB，非移植错误。
金丝雀测试只钉住纯正弦那一支：`psola::tests::near_octave_up_phase_cancellation_is_pinned`。
`absolute_lock_clamps_beyond_octave` 里钳位边缘的退化注释仍然真实，不要当已修。

踩过的坑：**不要用纯正弦/合成元音验收 ±10 半音以上的电平** —— 量到的是合成信号的
数值巧合，不是算法表现（Rust 的 `make_vowel` 恰好绕开了抵消区，给出虚假的安全感）。

## 测试单位 bug（已修）

`src/engine/rush/autotune.test.ts` 的 `centsOff` 写成 `1200 * (hzToMidi 差)`，而
`hzToMidi` 返回**半音** → 结果是真实音分的 **12 倍**，`toBeLessThan(40)` 实际卡在
3.33 音分。于是同一算法在阈值噪声里时红时绿（重写前 41.08 红、重写后 43.05 红，
真实误差都只有 ~3.5 音分）。已改为 `100 * (...)`，并补上「最后 0.1s 也必须被修到」
的尾段断言 —— 旧内核会在那条上以 1121 音分（漏一整个八度）失败。
