## 交付

### ① 电脑键盘弹奏（只发合成声）

- **新模块 `src/components/roll/keyboard-play.ts`**：纯映射层，无 DOM 副作用。
  - `KEYBOARD_SEMITONES`：A W S E D F T G Y H U J K O L P ; → 半音 0…16（Ableton/FL 同款）。
  - `KEYBOARD_OCTAVE_DOWN = 'KeyZ'` / `KEYBOARD_OCTAVE_UP = 'KeyX'`。
  - 用 `e.code`（物理键位）而 **不是 `e.key`** —— 中文输入法/键盘布局漂移会让 `e.key` 变成「a」以外的字。
  - `keyboardBasePitch(lanePitches, want)`：**夹取到键域 `[lo,hi]` 之后**吸附到最近 C。
    ⛔ 夹取区间只能是键域本身 —— 收窄会让 X 在窄键域彻底失效。
    ⛔ ref 里存**已生效值**，不存原始 wanted（否则用户加宽键域后基准自己跳八度）。
  - `resolveKeyboardNote(...)`：精确匹配，**匹配不到就落到最近的键**（自然音模式下黑键行仍有落点，
    → **没有死键**）。同分取低音。
  - `isTypingTarget()` 用**鸭子类型**（读 `tagName` / `isContentEditable`），不用 `instanceof HTMLElement`
    —— node 单测环境里没有 HTMLElement，会抛。
- **`useRollController.ts` 集成**：`window` 上挂 `keydown` / `keyup` / `blur`。
  - `e.repeat` 跳过；`isTypingTarget` 守卫；`[role=dialog]` 弹层开着时不弹奏；`Shift` 让位给编辑快捷键。
  - 按住延音：`playSynthNote(midi, { durationSec: KEYBOARD_HOLD_SEC = 30 })`，松手 `keyup → releaseSynthNote(midi)`。
  - `blur` → 全收（失焦时 keyup 收不到，会挂住长音）。
  - 新增 ref：`pressedRef`（按下行 Set）/ `heldKeysRef`（code→{pitch,lane}）/ `kbdBaseRef` / `kbdShiftsRef`（诊断计数）。
- **`src/engine/synth/index.ts` 新增 `releaseSynthNote(midi, fast = true)`**：
  非有限值直接 return，**不建 AudioContext**（只是收声，不该有副作用）。

### ② 按键高亮

- `renderer.ts`：`RenderState` 新增 `pressedLanes?: ReadonlySet<number>`。
  **直接传 `Set`**（`Set.has` O(1)），免每帧 `Array.from`。
- 三个位置同时点亮：白键行整条 `flame400 @ 0.5`；黑键行**只在黑键方块宽度内**点亮；时间线区叠 `flame300 @ 0.13`。

### ③ 左侧钢琴栏重做（消除「割裂」）

「割裂」的成因：原实现只在**黑键行**画方块，白键行是空背景 → 左栏看起来是一串
**互不相连的灰条 + 黑洞**，和时间线区没有分界。

新画法（每行，自上而下）：
1. 先铺**琴键面**：`ink800`，C 行 `ink700`（八度锚点）。**黑键行也不例外**。
2. 黑键行再叠方块：宽 `GUTTER_W * 0.58`，右缘高光 + 底缘投影。
3. `GUTTER_W − 1` 画 **1px 分界**，把左栏和时间线切开。
4. 半音键收起时画**凹槽**（`rgba(0,0,0,0.45)` + 强调色 0.42 描边）。

判据写进注释：**任何一行的左栏都必须有一条连续的面，洞就是 bug。**

### ④ 左栏点击（顺带）

- `onPointerDown` 在**命中测试之前** `return`：`pos.x < GUTTER_W` → 算 lane、点亮、试听（`previewPitch(pitch, 1)`）、
  `gutterPressRef` 记录。
- ⛔ 进不了拖拽/框选/插入音符状态机 —— **左栏 = 键盘、时间线 = 编辑**，左右分职。
- 半音键收起时不响应（那一行没有可点的键）。松手熄灯；按住期间不接受拖拽语义。

## 本轮踩到的坑（都是「安静」的）

### 1. 测试必须能证明「只发合成声」，否则下次有人顺手 import 采样

`roll-synth-only.test.ts` 是**读源码断言**：卷帘一族不许 import
`sample-player` / `take-player` / `engine/recorder` / `engine/exporter` / `engine/offline`，
同时必须确实调了 `playSynthNote`/`releaseSynthNote`，且 keydown/keyup/blur 三件套齐全。
理由：这个约束**坏了不会报错** —— 键盘弹奏突然开始播素材，只有耳朵能发现。

### 2. Z/X 改了基准却不重绘（真 bug）

基准变了但没标脏 → 快照永远是上一帧，**看起来像「X 键无效」**。
修复：Z/X 分支**无条件** `dirtyRef.current = true`。

### 3. 探针读 canvas 快照读到上一帧

`__rollKeys` / `__rollView` 是渲染循环在 `draw()` 里写的 → 派发事件后**立刻读**拿到的是旧值
（曾据此错判 X 无效：60 → 60）。**正解：读前 `await` 若干 `requestAnimationFrame` + `sleep(40)`。**

### 4. 诊断字段要能区分「没进处理函数」vs「被夹取」

`wanted: kbdBaseRef.current` 分不清这两种情况 → 改成 `shifts`（处理函数执行计数）。
**加诊断字段的目的是排除可能，字段本身不能又有歧义。**

### 5. 探针行高不能自己算

第一版用 `(rc.height - 22) / 24` 算行号，在 61 键域下算到错行（`pressed=[29]` 期望 `[12]`）。
**正解：从 canvas 上挂的 `__rollView.rowH / sy` 读权威行高。**

### 6. 模板字符串里的反引号

探针 `inject()` 的模板字符串内写了 `` `__rollView` `` → `SyntaxError: missing )`。
改成纯文本。

### 7. HMR 让 `import()` 拿到另一份 store 实例

改源码后 `import('/src/model/store.ts')` 拿到带 `?t=` 的另一份 → `hydrated` 永远 false、注入不生效。
**正解：重启 dev server。**（已与 `REF-frontend.md §8` 记载一致。）

## 诊断：「启动项目后网页迟迟打不开」（用户报）→ 已修

### 真凶：dev server 只绑一族 + 本机不给 RST

| 实测 | 结果 |
|---|---|
| `netstat` 看 5173 | **只有 `[::1]:5173`**（默认 `host='localhost'` 在 Windows 上解析到 `::1`） |
| `curl http://127.0.0.1:5173` | **code=000，2.37s 才失败** —— 根本连不上 |
| 死端口（谁都没监听）失败耗时 | IPv4 **2.44~2.64s** / IPv6 **2.35~2.44s** |
| 只绑 `[::1]` 时访问 127.0.0.1 | 2.37s 失败 |
| 只绑 `127.0.0.1` 时访问 `::1` | **2.04s 失败** ← 镜像问题，两个方向都有 |

**本机（系统代理 127.0.0.1:10809 开着）对无人监听的端口不回 RST，SYN 被丢掉**，
连接必须干等约 2 秒。于是「只绑一族」= 另一族每次访问白付 2s，而浏览器对
`localhost` 两族都会试 → 用户感知就是「迟迟打不开」。

### 修法 + 效果

`vite.config.ts`：`server.host = '::'`（**双栈**）。实测 Node 下 `::` 同时吃 IPv4/IPv6
（IPv4 200 / IPv6 200，IPv6 仅 10ms）；Vite 重启后 `netstat` 显示 `0.0.0.0:5173` +
`[::]:5173` 两个 LISTENING，三种地址都 **3~9ms** 返回 200。

| | TTFB | DCL | LOAD |
|---|---|---|---|
| 修前 `localhost` | 1291~3008ms | 5855~9825ms | 5870~10215ms |
| 修前 `127.0.0.1` | **打不开**（Chrome 错误页） | — | — |
| **修后 `localhost`** | **277ms** | **1357ms** | **1364ms** |
| **修后 `127.0.0.1`** | **172ms** | **1288ms** | **1291ms** |

⛔ 试过 `'127.0.0.1'` —— IPv4 立刻好了，但 IPv6 那侧照样 2s，**不是正解，别改回去**。
代价：`::` = 监听所有网卡，dev server 对局域网可见（顺带方便手机连过来验收）。
不想要暴露就改回 `'127.0.0.1'` 并且**只用 `http://127.0.0.1:5173` 访问**（别用 `localhost`）。

## ⏳ 待用户拍板：演奏台的「电子音」到底要不要静音采样

`StagePage.playNote` 在 `voiceMode === 'synth'` 时**先照常 `handlePress`**（→ KeyMachine
→ `getMasterChain().input`，**采样照播、照过 EQ/混响**），**再叠加** `playSynthNote`。
所以「声部 = 电子音」时耳朵听到的是**采样（带混响）+ 合成声**两层。

而 UI 上那是个 `Seg`「声部：采样 | 电子音」，且 `PlayModeView` 的注释写着
「采样声部压根不经过合成器」—— 语义上像是**互斥**的二选一。

**已确认可用的修法**（未实施，等用户确认）：`KeyMachineConfig.resolveBuffer` 在
「未命中返回 null」时会**游标照常推进**（`哑触发`），所以只要在 `voiceMode==='synth'`
时让它返回 null，就能做到「游标/动画照常、采样不出声、只剩干净的合成声」—— 不用新 API。

⛔ 不实施的理由：现有注释写的是「额外叠加」，可能是有意的参考音设计（09-25 日志里
合成声的定位是「试听参考声」）。**这是听感/产品决策，按项目规矩交给用户。**

## ⭐ 修复：合成声「些预设一直响」+「按多了卡顿 → 没声」（用户报）

用户原话：「电子音是不是有bug 有一些预设会一直发声(混响的回音) 还有就是 按的多了 就会声音卡顿
然后 没声」。**核查结论：两个症状是同一根因的两个表现**，不是混响 bug，也不是性能不足。

**根因三条（老代码）**：

1. **回收漏了**：`noteOff` 老写法是 `voices.delete(v)` 之后才 `release(v)`，而清扫器 `sweepVoices`
   只遍历 `voices` → **被显式释放的声部再也不可达、永不被 `dispose()`**。后果：① 残留在音频图里
   一直响；② 每次按键漏约 20 个节点（声部节点数），几十次按键后音频线程顶不住 → 卡顿 → 没声。
2. **释放不静音**：`AudioParam` 的实际值 = 内置值 + 所有连入信号之和，而 LFO 是**直连** `amp.gain` /
   `filter.frequency` 的 → 包络斜坡到 `MIN_GAIN`(1e-4) 只是让增益在 `1e-4 ± lfoAmpAmt` 之间摆，
   照旧出声。**且 `disconnect()` 无法排程到未来时刻**，而 `release()` 有一半调用来自 `noteOn` 内部的
   「自动释放排程」→ 在那儿断开会把**正在响的音的颤音当场摘掉**（第一版修复就栽在这里）。
3. **滤波器在包络之前**（`mixer → filter → amp`）：包络归零只能乘小滤波器的输出，压不住高 Q 滤波器的
   自激（振荡器要到 `dispose()` 才 `stop()`，释放后仍被持续喂信号）。

**修法（`src/engine/synth/engine.ts`）**：

- 声部私有、**可排程的调制深度级** `lfoAmpDepth` / `lfoFilterDepth`（增益=1 时与直连等价，音色不变；
  音频参数 LFO 仍直连 `osc.detune`，它产生不了输出）。释放时 `setValueAtTime(0, at)` 精确归零。
  深度为 1 时试听探针能量比 4.31，证明没误伤颤音。
- `release()` 改为幂等 + 补 `setValueAtTime(0, at + rel)` **以精确 0 收尾**（指数斜坡到不了 0；
  残留 2e-4 会被高 Q 共振抬回可闻）。
- 引擎层新增 `dying` 集合 + `retire()` / `killVoice()` / `voiceStats`；**所有释放一律经 `retire()`**，
