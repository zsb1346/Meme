## 1. 定稿（2026-09-20，用户六项全按推荐值拍定）

| 项 | 定稿 |
|---|---|
| 八度约定 | **C4 = 60**（科学音高，与 `.mid` 一致）。FL Studio 把同一个音叫 C5，差一个八度，接受 |
| 开关迁移语义 | **音高守恒**（老工程一个音都不跑），⛔ 不采纳「按下标重算」 |
| 音域 | **C3–C8**（起点 `KEY_BASE_MIDI=48`、上限 `KEY_MAX_MIDI=108`） |
| 半音几何 | **钢琴几何**（黑白键），不是 12 等分格 |
| 到顶之后 | **停住并提示**，⛔ 不绕回低音区 |
| 音名粒度 | **一律带八度数字**（`C4`），唱名全删 |

用户原话：「半音需要设计一个开关去打开/关闭 …… 按行算 一行代表一个8度」，
并追加 **手机适配**（手机上没键盘，装配素材是最难的一环）。

## 2. `src/model/pitch-map.ts` —— 单一事实来源

导出清单（新代码只准用这些）：

- `KEY_BASE_MIDI = 48`（C3）/ `KEY_MAX_MIDI = 108`（C8）/ `LEGACY_BASE_MIDI = 60`
- `MAJOR_STEPS = [0,2,4,5,7,11]`、`DIATONIC_PER_OCTAVE = 7`、`SEMITONES_PER_OCTAVE = 12`
- `midiNoteName(midi)` → `C4` / `isBlackMidi` / `isDiatonicMidi`
- `keyPitch(key, keyIndex)` —— **权威音高 = `key.pitchMidi`，缺省才回落旧映射**
- `nextSequencePitch(after, chromatic)` —— `after===null` → C3；超上限 → **null**
- `sequencePitchAt(index, chromatic)`、`maxKeyCount(chromatic)` = 36 / 61、`keysPerRow()` = 7 / 12
- `legacyPitchOfLane(lane)` —— **只准两处用**：旧存档迁移 + 缺 `pitchMidi` 的兜底

⛔ 「起点 C3」是用户明确定的**标准**；C3..C8 跨 **5 个八度**（不是 6），
`maxKeyCount` 自然音 = `7*5+1 = 36`。这个 +1 是终点 C8 那个键，容易漏。

## 3. 为什么「键的身份必须是音高」

用户的诉求是「21 个音频留给我们发展的空间并不高」，根子**不在数量，在模型**：

原模型里 `keyIndex` 是**位置**，音高由位置**推导**（`geometry.pitchOfLane`）。
于是「第几格 = 是哪个音」绑死，像一栋 7 层的楼，住哪层就是哪个音。
半音开关一开 → 每两层之间插一层 → 7 层变 12 层 → **原来住 2 楼的 re 卡住了**：

- **保住音**：它还是 re，跟着挪到 3 楼 → 老工程打开一个音都不变 ✅（用户选这条）
- 保住格子：它留 2 楼，但 2 楼现在叫 do# → **一开开关老工程集体走音**
  （第 2 个音降半音、第 3 个降全音、第 4 个降三个半音…）

改成「身份 = 音高」之后，位置与音高**解耦**，开关才可能只影响未来。

## 4. 迁移（`store.migrateProject`）

- `settings` 一律「`DEFAULT_SETTINGS` 打底 + 存档覆盖」（未来新增字段自动生效）。
- 键：按 `legacyPitchOfLane(i)` 逐点补写 `pitchMidi` → **迁移前后每个键的音高逐点一致**。
- 标签：**仅当匹配出厂图案** `/^(?:do|re|mi|fa|sol|la|si)['′]*$/` 时改写为音名；

## 5. 键位矩阵 `KeyLayout.tsx`

两种几何由 `chromatic` 切换：

- **自然音**：恒定 7 列网格，行内极轻抛物线上扬（arcH 5px）+ 切线倾斜（1.6°）。
- **半音（钢琴）**：每八度一行；**恒定 7 个白键槽位铺底**，黑键绝对定位压在缝隙上
  （高 58%、宽 ≈ 白键 62%），位置公式
  `left = calc(b·100/7 % + (b·8/7 − 4)px)`，`translateX(-50%)` 居中，`b = BLACK_BOUNDARY[chroma]`
  （C#→1 D#→2 F#→4 G#→5 A#→6）。

### ⛔ 两个实测抓到的 bug（都会「画面直接骗人」）

1. **尾组拉伸**：原写法 `repeat(Math.max(whites.length, 1), …)` —— 只剩 1 个白键的尾组
   只给 1 列，那个键**被拉满整行宽度**，且与上方的 C **错位**。
   → 改**恒定 7 列 + 空列渲染占位**。
2. **白键按数组顺序填格**：尾组里只有一个 D（`C#` 之后追加）时，按顺序会把它摆到
   **第 1 列（C 的位置）**。→ 必须按音级落列：`WHITE_COL = {0:0, 2:1, 4:2, 5:3, 7:4, 9:5, 11:6}`。

`MemeKey` 的 `black` 变体：面比白键深一级（`ink-950` + `border-black/60`）、
圆角收到 3px、字号降一档、**不显示素材名**（键太窄）。

## 6. ⛔ `setKeyCount` 的预设回弹会吃掉大半个音域

`StagePage` 里有

```ts
useEffect(() => setCountOption(7/14/21/custom), [keyCount]);
```

**无条件回弹** → 键数一到 **21（恰好是预设值）**，选择器跳回预设、**步进器被卸载**。
用户以为「到头了」，其实只是 UI 把路收了。音域扩到半音 61 键后，这一下吃掉 40 个键。
→ 改 `prev === 'custom'` 时**保持 custom**，让步给用户的选择。

（实测症状：脚本连点步进器 `for(i<13)` 在第 7 下停住，计数停在 21。）

### ⛔ 同一个 `--eval` 里连点多个控件，只会生效最后一个

React 18 在**同一个事件任务内批处理 setState**，`keyCount` 是**渲染闭包里的旧值**：
`for(i<8) plus.click()` 八次都算成 `14+1=15`（实测只 +1，不是 +8）。

两条正确姿势：
1. **拆成多个 `--eval`** —— 脚本在两条之间 `sleep 180ms`。
2. 写 `async` 函数，**每次点击后 `await setTimeout(70~90ms)`**，让每击成为独立任务。

对应地，**「点导航」与「点页内控件」也必须分开两条 eval** ——
同一条里页内控件还没渲染出来，选择器必然落空（实测 `semi:false`）。

# 11. 2026-09-25 交互审计：四条真 bug（已修）+ 四条待拍板

用户原话：「你刚刚设计的半音 如果打开的话 可以添加半音 但是 关闭的话 半音会被当做
音符块挤占其他的地方 / 再者 钢琴卷帘似乎也还没有配合 半音 的出现 / 以及一些适配的细节问题」。
逐条核实，**两条属实且比用户说的更严重，另两条是我顺出来的**。

## 11.1 ⛔ 布局曾被「半音开关」驱动 → 关掉开关黑键变白键格子（已修）

旧实现 `KeyLayout` 有**两套几何**：`chromatic=false` 走 `DiatonicGrid`（**按下标顺序**填 7 列），
`chromatic=true` 走 `PianoLayout`。调用点是 `chromatic={semitoneMode}` +
`black={semitoneMode && isBlackMidi(...)}`。

后果（用户实报的「挤占」）：开着半音加过 14 个键（C3…C#4）后关掉开关，
`DiatonicGrid` 按数组顺序排 → 第 1 行变成 `C3 C#3 D3 D#3 E3 F3 F#3`，
C#3 **变成一个白键格子**、占掉 D3 的位置，「一行 = 一个八度」当场崩掉。

**根因**：把「一个键长什么样」和「下一个新键取哪个音」混成了同一个开关。
**定稿规则**：**布局永远由 `Key.pitchMidi` 决定，与开关无关；开关只剩一个含义
= 新增键时取自然音序列还是十二半音序列。** 这样「开→关」与「关→开」都无损。
弧线只在该行**没有黑键**时保留（有黑键的行转平 —— 黑键绝对定位在白键缝上，跟弧线会错位）。

## 11.2 ⛔ 卷帘比键盘高一个八度（已修，且这才是「卷帘没配合半音」的直接原因）

`RollCanvas` 有 `lanePitches` 契约，但 `StudioPage` **从来没传过**（全仓 grep 只有
定义处与 controller 内部引用）→ `renderer.ts` 回落到 `pitchOfLane = legacyPitchOfLane`
（lane 0 = **C4** = 60），而键 0 的权威音高是 `sequencePitchAt(0)` = **C3** = 48。

两个可见症状：
1. 键盘写 C3 D3 E3…，卷帘左侧钢琴栏写 C4 D4 E4… —— **同一屏差一个八度**；
2. 回落的旧映射把**每一行都当白键** → **开着半音也不出现黑键行**
   （用户看到的「卷帘没配合半音」就是这个）。

修：`StudioPage` 传 `lanePitches={keyPitches}`；兜底锚点改 `sequencePitchAt(lane,false)`
（与键域起点一致），**不允许再出现第二个锚点** —— 漏传的代价是「静默差一个八度」，
看起来像算法错了。

## 11.3 ⛔ 关掉半音后点一下键数 → 静默砍掉 25 个键（已修）

`setKeyCount` 曾用 `maxKeyCount(chromatic)` 夹取：自然音 36 / 半音 61。
半音模式下的 61 键工程把开关关掉后，PlayModeView 的 ＋ 做
`Math.min(maxKeys=36, 61+1)` → `setKeyCount(36)` → **当场截断 25 个键（连装配一起丢），无任何提示**。

**规则**：键数上限**与模式无关**，用 `KEY_DOMAIN_MAX_COUNT`（= 键域格数 61）。
自然音模式真正到不了 61 —— `createNextKey` 走到 C8 返回 null，`while` 自己会停。
UI 的 ＋ 禁用条件也随之改成「序列下一个音是否为 null」（`nextSequencePitch`），
提示语能说出「下一个是 D5」/「已到最高音 C8」。

## 11.4 死代码：三份唱名/音名重复实现（已删）

`midi-import.ts` 尾部的 `laneToSolfege` / `laneToOctaveGroup` / `midiToNoteName` /
`SOLFEGE_NAMES` / `PITCH_CLASS_NAMES` 已**零外部引用**（全仓 grep 确认），
却仍在导出唱名 —— 正是「音名只有一份」这条规则的定时炸弹。整段删除。

## 11.5 ⛔ 卷帘纵向距离与音高**不成正比**（未改，待拍板）

自然音键集下 `C3→D3` 是全音、`E3→F3` 是半音，但卷帘**行距一样**（行 = 键，不是音高）。
真钢琴卷帘里纵向距离 = 半音距离。三个选项：
- 甲：卷帘纵轴改**音高轴**（半音精确），缺的半音画「幽灵行」（压暗、不可放音符、
  留一个「+」可就地建键）。代价：`laneOf / yToLane / contentH / hitTest` 全要动。
- 乙：保持「行 = 键」，承认它是七音排琴而非钢琴。零成本。
- 丙：行距按半音数**成比例**（gap 累积偏移），不做幽灵行。中等成本，纵向还是 1 行 1 键。

## 11.6 ⛔ MIDI 导入后「键名」与「实际发声」差 N 个半音（未改，待拍板）

`laneOffset = -minLane` 把**歌曲最低音对齐到键 0**（键 0 的音名是 C3）。
实测例：音域 G4..D6 → 落在键 0..19 → **一个 G4 的音符坐在标着 C3 的键上**，
卷帘那行写 C3、耳朵里是 G4，差 19 个半音。
（注意：`baseOctave=4` 那个锚点**不影响** lane 分配 —— `laneOffset` 会把锚点约掉。
真正的病是「键名」与「事件音高」脱钩，不是锚点。）

选项：甲 导入时把**键域整体移到歌曲音域**（键名 = 真听到的音，代价：起点不再是 C3）／
乙 保留从键 0 起，但明确提示「已适配：相差 N 个半音」且**卷帘那行显示事件音高**／
丙 不自动适配，超域音符直接丢并报告。

# 12. 键数预设：口径从「键数」改成「八度」（2026-09-25 修）

用户一句话把 §11.7 的最后一条摆上台面：
「不是有一个预设键数吗 把数量调整一下 普通的无半音数量和有半音的数量 这边你设计一下」。

## 12.1 口径：为什么用八度数，不用键数

| 档位 | 无半音 | 有半音 | 覆盖音域 |
|---|---|---|---|
| 1 个八度 | 7 键 | 12 键 | C3–B3 |
| 2 个八度 | 14 键 | 24 键 | C3–B4 |
| 3 个八度 | 21 键 | 36 键 | C3–B5 |
| 自定 | 1–61 逐键 | 1–61 逐键 | C3–C8 |

`n` 个八度 → 自然音 `7n` 键 / 半音 `12n` 键，**最高音恒为 `48 + 12n − 1`**。

同一档在两种模式下覆盖**完全相同的音域** —— 打开半音只是把这段音域**切得更细**
（14 键 → 24 键），不是把范围换掉。旧口径下「21」在半音模式里是 **1.75 个八度**
（C3–G#4，收在一个黑键上，没人会要）。附带好处：`count` 恒等于 `keysPerRow × n`
（整数行），键位矩阵排出来永远是满行，不剩尾组。

**单一来源**：`pitch-map.ts` 的
`keyCountPresets / presetOctavesOfCount / countOfPresetOctaves / KEY_COUNT_PRESET_OCTAVES`。
⛔ UI 里不许再出现 7/14/21 字面量（原先散在 3 处：`PlayModeView` 的 `CountOption`
联合类型 + options、`StagePage` 的 useState 初值 + 回弹 effect）。

**`CountOption` 的值从键数改成八度数**（`'1'|'2'|'3'|'custom'`）—— 它现在
**必须带模式才能解释**（`countOptionOfCount(count, chromatic)`）。label 也从 `7/14/21`
改成 `1 八度/2 八度/3 八度`，title 给出「n 个八度 · x 键 · C3–Bx」——
否则「键数：1」会被读成「1 个键」。

**⚠️ 初值/回弹 effect 必须带模式**：14 键在自然音下是「2 个八度」，在半音下什么都不是。
带模式还带来一个**诚实**的副作用：打开半音开关时若当前键数不构成整八度，
选择器会落到「自定」并显示 14 —— 因为 14 键在半音模式下确实是 1 个八度 + 2 个半音。
（旧写法用错模式判定会让选择器说谎。）

## 12.2 ⛔ 顺出来的真 bug：档位 + 切模式 → **音域漂移**

预设一旦是"音域"语义，`setKeyCount` 的"数量"语义立刻露馅：

```
自然音 14 键（C3–B4）+ 打开半音 + 选「3 个八度」
→ setKeyCount(36) 从**最后一个键 B4** 往后接半音键（C5 C#5 …）
→ 得到「C3–B4 全白键 + C5–A6 半音」，音域跑到 A6
```

用户点的是「3 个八度」，拿到的是 **C3–A6**，而且前两个八度没有黑键。
根因：`createNextKey` 基于"最后一个键的真实音高"续排 —— 同模式内正确，
但**混合键集**（旧模式留下的键）下会把音域推宽。任何操作顺序都会中招
（先点档位再开半音更糟：21 + 15 = C3–C7）。

**修法：把两个动作彻底分开**

- `setKeyCount(n)` —— **数量**语义：「＋/−」步进器走这条，增删末尾，
  **一个已有键的音高都不改**（老工程永不跑音）。
- `realignKeys(n)` —— **音域**语义：档位走这条，第 `i` 个键的音高 = `sequencePitchAt(i)`，
  **保留装配**（`sequence` / `cursor` / 按键绑定按位置留下），只改 `pitchMidi` 与
  **自动生成的**音名标签（`label === midiNoteName(旧音高)` 才改写；用户手改过的
  标签保留 —— 与迁移策略同一条规则）。

⛔ 两者**不许合并**，任何一边沾上另一边的语义都会出事：
档位走数量 → 音域漂移；「＋」走音域 → 用户只加一个键，整个键盘被静默重排。

hook 侧 `applyKeyRange` 在重排前数清「有几个已有键要被移动」，> 0 就 toast
（实测文案：「键集已按半音音阶重排，13 个已有键的音高随之移动（装配保留）」）。
**移动已有键的音高必须让用户知道** —— 否则「我装的素材怎么变调了」是一条
查不出原因的投诉。键集本来就规整时（最常见路径）不弹任何东西，零行为变化。

回归测试：`src/model/key-range.test.ts`（7 例，含「setKeyCount 绝不重排」这条反向断言）。
