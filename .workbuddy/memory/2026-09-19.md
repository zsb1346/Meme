昨天的重写只统一了变调路径；`wasm/src/autotune.rs` 还挂着一个自动修音专用合成实现

  删掉 `split_voiced` / `Segment` / `build_marks` / `unvoiced_synth` / `hann_at`
  这批只服务旧路径的死代码（`Mark.period` 字段也一并删掉，唯一读取方已不存在）。
- 模块编号前移补空洞：A F0 轨迹 / B pitch marks / C 合成内核 / D 曲线合成 / E 变换流程。

## 用户报的三个症状：根因全部定位并修掉

用户原话：「我们之前不是重写了合成内核吗 变调和调速度，为什么没接上呢?
症状是：在装配面板按 Shift+上下 部分音频素材没有变调；变调的声音听着也没 PitchNet 好；
自动修音功能失效。」

内核**确实是重写好了的**（09-18/09-19 两条记录），问题在**检测层**和**降级链**。
三条症状共用同一个根：**逐帧 YIN 在真素材上大面积漏检**，而两条下游都靠它。

### 症状 1「部分素材没变调」

**根因**：PSOLA 对无周期素材（短切片/带音效/噪声型）逐帧一帧都过不了 CMND 阈值
→ `frames` 全 unvoiced → 每颗颗粒落到**固定颗粒路径**，而固定颗粒的推进量是常量
（不随 ratio 变）→ 输出等于「按时间映射重采样原声」，**音高完全没动**。
致命之处：它**照样返回合法音频、不抛异常**，而 `playSample` 的降级链（PSOLA →
SOLA → 原声）是靠 `catch` 推进的 → 永远认为 mode=1 成功了。
实测真素材 **13/41 静默不变调**（输出与源逐样本相同，频谱质心比恰 1.000）。

**修**：三道。
1. `yin_core.rs` 新增 `autocorr_frame`（自相关 + 谐波性 + CMND 并列裁决），
   `psola.rs::yin_frame` 在 YIN 返回 None 时兜底。**不放宽 YIN 阈值** —— 实测放宽到
   0.30 会让「豆.mp3」从 360.6Hz 跳到 721.0Hz（二次谐波），八度错比不检出更糟。
2. `psola.rs` 新增诊断计数 `LAST_VOICED`（voiced 帧数 + mark 数），
   `stretch.rs` 导出 `hajimi_tx_voiced_frames` / `hajimi_tx_marks`。
3. **降级链接线**（本次收尾的那一环）：`transform.ts::isPsolaSilentNoop(mode, pitch,
   marks, voiced)` 把「成功但没做事」翻成 `PsolaSilentNoopError`，`playSample` 照旧
   catch → 推进到 SOLA。判据用 **marks===0**（渲染时每颗颗粒要过
   `voiced && !marks.is_empty()`，marks 空则整段都没做颗粒重排），并排除 pitch≈1
   （纯拉伸时固定颗粒路径是预期行为）。另加 `psolaNoopBuffers` WeakSet，
   同一素材不必每次重放都白算一轮 PSOLA。

### 症状 3「自动修音失效」

**根因**：`store.detectedPitchHz` 来自 `hajimi_detect_pitch`（YIN），**14/41 漏检**
→ null → `sampleSemitonesAtPitch` **静默退回** `manualSemitoneOffset`（默认 0）
→ 开关按下去毫无效果。UI 接线本身是对的（`StudioPage` → `setAutoTuneEnabled` → store）。

**修**：`yin.rs::autocorr_fallback` —— 自相关兜底 + **帧间一致性闸门**
（过闸的帧里须有半数以上 ±100 音分互相同意，否则返回 0）。
「绿.mp3」这种「YIN 与神经检测都拒检」的素材因此仍然得到 null（行为不比从前差），
而真正的短切片能拿到可信音高。

### 症状 2「音质不如 PitchNet」

**没有找到实现层面的缺陷**，反而测出内核是健康的：
- `measure-autotune.mjs`：四段 F0 误差 0.4~3.7 音分、时长守恒、长清音段逐样本放行、
  稳态响度比 1.0001、起音跳变峰 0.08。
- 新建 `_probe-material-level.mjs` 量了 41 个真素材在 ±5/±7/±12 半音下的中段电平比：
  **中位 1.000，最差 0.83，没有一个薄到 0.70 以下**；+12 半音处质心比只有 1.034
  （pitch 比 2.000）→ 证明走的是颗粒重排路径、共振峰没动。
  这把 `psola.rs` 模块头那张「+12 半音塌到近静音」的合成信号表**定性成验收信号问题
  而非真实素材问题**，那段注释已按实测改写。
- 剩下的可疑项只有「用户听的是旧 wasm / 旧缓存」—— 本次已重建产物。

## AI 音高检测（basic-pitch）—— 检修完成，那条线闭合

用户要求：「检查一下我们项目的 AI 检测音高，必要的时候可以让他更稳健。」
前一轮只留下「CPU 后端推理超时」的猜测，这次在**真浏览器里跑生产 worker** 逐条落实。

### 三处真实缺陷（都有真浏览器实测）

1. **AI 永远「未检出」**：worker 喂 4s（= 3 批模型）而主线程只给 15000ms。
   真浏览器实测 4s@48000（素材真实路径）**= 15076ms > 15000ms** → 每次必超时。
   砍到 `AI_SECONDS = 1`（= 1 批），复验 **15076ms → 3187ms**。
2. **模型加载失败不可恢复**：`new BasicPitch(url)` 不 await 权重，坏实例被永久缓存；
   失败的 promise 也被缓存。→ `await model.model` 确认后缓存，catch 里清空。
3. **YIN 有两份实现，兜底只加在 Rust 侧**：面板走 JS `detectPitchYinCore`，
   导入走 wasm `hajimi_detect_pitch`。41 个真素材：**wasm 未检出 2/41、JS 未检出 15/41**，
   且 JS 的可用结果全被 wasm 覆盖。→ Rust 新增 `hajimi_yin_f32`（`yin::detect_pitch_opts`
   参数化），`pitch-worker.ts` 的 yin 分支改走 wasm，JS 版降为「wasm 加载失败」的应急退路。

### AI 弃权：不是模型不知道，是门太窄（本轮最有价值的发现）

`scripts/probe-ai/probe-ai-threshold.html` 的设计要点：**推理只跑一次**，
之后不同阈值只是重跑 `outputToNotesPoly`（纯 JS、微秒级），否则 4 组阈值 = 4 倍推理时间。

结论（41 个真素材）：

- `frames` 为空（模型真的没输出）**0/41** —— 模型从不说「不知道」。
- 严格档（库默认 0.25/0.25/5）一个音符都切不出来的 **6/41**。
- 逐档扫「有没有把对的答案改坏」：**0.2/0.2/4 召回 5/6、新增灾难 0**；
  0.15/0.15/5 出现 `啊.mp3` +1797¢ 幻觉；0.1 档 4 个新增灾难。

落地成 **严格档优先、切不出音符才用放宽档**（`AI_NOTES_STRICT` / `AI_NOTES_RELAXED`），
放宽档只重跑后处理、模型不重跑，几乎零成本。

### 「换窗口重试」要诚实说明

本来按「最响的一秒可能是鼓点」写了 `candidateWindows` + `AI_WINDOW_TRIES=3`。
实测发现 **41 个真素材全部只有 1 个候选**（这批切片最长 1442ms、中位数约 260ms，
比 1 秒窗口还短的一大把）→ 对短切片它根本不生效，真正救弃权的是阈值兜底。
保留它（对**导入的长音频**有意义），但注释已按实测改写，不再谎报收益。

## 技术债清理：emoji 清理 + 编码体检（用户报「中文注释乱码」）

### 「乱码」的真实结论：不是字节坏了，是 emoji 视觉干扰

全仓编码普查 3847 个可读文本文件：3724 UTF-8 / 9 UTF-8-BOM / 105 真二进制 /
**1 非 UTF-8**。那 1 个是根目录一个错误 shell 重定向的游离文件（已删），**不是源码**。
判据用「GBK 往返还原」（把 UTF-8 被当 GBK 解码的产物编回字节，看是否恰好是合法 UTF-8 且解出中文），
关键字表会漏。**结论：源码与文档没有真乱码** —— 用户感知的「乱码」就是 emoji 显示干扰。
所以「恢复注释」这一项没有落地动作（重写中文反而会真的改坏），只做了 emoji 清理。

收尾复测（自有代码+文档 251 个文本文件，排除三块 vendored 源码）：UTF-8-BOM 7 /
二进制 0 / **非 UTF-8 0**；GBK 往返命中 2 条，**都不在源码里** ——
`.probe-wasm-exports.txt`（探针 scratch 日志，`.gitignore:28` 已忽略，中文路径被写成
`F:\L纁…鍝…`，成因就是那条 PowerShell 重定向坑）+ 技能文档自己引用的乱码示例。
**判据本身不误报，两条都是真命中**；关键是要看命中落在哪个文件。

## 「爆音/杂音」定位：Σw 归一的 floor 被当成闸门（用户报，已修）

用户原话：「我们唯一的工作就是音频、音质。你之前重写过合成器内核，音质有提升，
但我现在遇到的是爆音/杂音问题。参考项目 PitchNet 好像有对此的修复，
你可以比对一下 PitchNet 和我们的源代码，看看能不能定位出来问题。」

### 先确认：PitchNet 那些咔哒修复我们**都已有**

快照是 `原型/PitchNet-master/`（`CMakeLists` 里 `project(PitchNet VERSION 0.5.7)` =
最新版，releases 里 v0.5.5「Fixed clicks during rendering」、v0.3.1「Refined
resynthesis algorithm to avoid clicks」的提交**都在里面**）。逐行比对
`PsolaSynthesizer.cpp` ↔ `wasm/src/psola.rs`：onset anchor 吸收、`grainHalf >= ceil(advance)`、
`MIN_ENVELOPE` floor、`applyLocalGainMatch`（MIN/MAX_GAIN 0.25/4.0、SMOOTH_RADIUS 2、
无输出上限）**全部一致**。所以「缺 PitchNet 的修复」不是原因。

PitchNet 那些 release note 里的咔哒修复，大头其实在 `IncrementalSynthesizer.cpp`
（768 样本 smoothstep commit fade + `findBestCommitSpliceCenter` 拼接点搜索 +
`findBestSpliceCenter` 定时补丁），那是「把渲染结果缝回已有波形」这一层；
我们整段离线渲染，没有这一层，也就没有那类缝。

### 真正的根因：`synth_channel` 的 Σw 归一写成了闸门

```rust
// 修前 —— 逐行照抄 PitchNet 代码，但 PitchNet 自己的注释说的是另一回事
if w > MIN_ENVELOPE { synth[i] = padded[i + pad] / w; }   // 否则留 0
```

PitchNet 的注释：「用 floor 留下**平滑的幅度凹陷**」。它的代码却是
满幅 ↔ 精确 0 的硬跳变。触发条件由几何唯一决定：接缝处 Σw = 2·Hann(A/2)，
voiced 路径 A/grain_half = 1/ratio → **ratio < 2/3 也就是 -7.02 半音**起，每个周期跳一次。

`_probe-clickcount.mjs`（新增）逐素材数「比源多出来的咔哒簇」，
沿参数轴扫出**台阶**（增簇中位）：`-5 → +1`（未触发）`-7 → +11` `-9 → +30` `-12 → +24`
（单素材最大 +753）。台阶精确落在 -7，与几何推导吻合。

### 修法

`synth[i] = padded[i + pad] / env_kept[i].max(MIN_ENVELOPE)` —— 给除数下下限。
w = 0.3 两侧都是 `padded/Σw`，天然连续；w→0 时按 w 平滑收敛到 0。

| 档位 | 增簇中位 | 增簇最大 | >源+3 素材数 |
|---|---|---|---|
| -7 | +11 → **0** | +76 → **18** | 32 → **15** |
| -9 | +30 → **4** | +311 → **30** | 32 → **23** |
| -12 | +24 → **6** | +753 → **138** | 28 → **24** |
| +5 / +7 / +12 / 恒等 | 不变（逐样本） | 不变 | 不变 |

精确 0 样点（`基` @0.5，后 70%）：**23.06% → 1.51%**（源基线 0.23%）。
副作用（好）：-12 的峰值增量中位 1.216 → **1.152**、max 1.356 → **1.283**；
中段跳变比最差（-5 档）2.15 → **1.33**。
**中段电平比不变**（41 素材 ±5/±7/±12 中位仍 1.000，无一 <0.70）。

为什么只在降调触发：升调时 advance = grain_half/ratio < grain_half → 重叠 **>50%**、
Σw **>1**，`max` 永不介入；所以全部升调档与 unity 逐样本不变。

- `vocoder_*.txt` → `Loading model from: C:\ProgramData\Session Loops\PitchNet\models\pc_nsf_hifigan.onnx`

**结论**：他从没听过 PitchNet 的 PSOLA。`liveAuditionEnabled:false` 还说明路径①（拖动试听）
在他机器上是**关着的** —— 所以上一轮我推的「拖动试听 = 纯重采样」方向对但**不是他在听的路径**。

### 声码器为什么「干净又舒服」：mel 不变、只换 F0

- 模型 2 输入：`mel[T,128]` + `f0[T]`（`Vocoder.cpp:411` 张量数 / shape 维度可证；日志只打印
  `inputNames[0]` 容易误读成一个输入）。
- `IncrementalSynthesizer.cpp:1200` mel 直接取自导入时预算的 `audioData.melSpectrogram`，
  **变调不动 mel** → 频谱包络固定 = **共振峰天然保持**，NSF 再用新 F0 生成干净的周期激励。
- mel 参数：`nFft=2048 / hop=512 / n_mels=128 / fMin=40 / fMax=16000`，log 刻度（`MelSpectrogram.h`）。
- `hnsep_VR.onnx`（92MB）在 `Source/` 里**零引用**，不是管线的一部分。

**所以「我们沙沙」= 算法类别差**（重排源的真实样本 vs 模型生成波形），不是端口 bug。
要真正对齐只有接神经声码器（onnxruntime-web 跑 FCPE + HiFiGAN ≈ 99MB 权重，离线可行）；
PSOLA 内部能做的最优是**谐波/噪声分离后只对谐波做颗粒重排**。

## 续：把「降调沙沙」定位到机制，并落地为 mode 3

上一轮说「拆分后只对谐波做颗粒重排」是最优解 —— 这轮做完了，也把它量化了。

### 决定性实验：颗粒几何不造噪，造噪的是**被重排的非周期内容**

同一套 marks、同样的颗粒几何，只换喂进去的内容（`scripts/_probe-hnsep.mjs`，龙.001 @−8.23 半音）：

| 喂给内核的内容 | 输出 HNR | 周期性 |
|---|---|---|
| 原始素材 | 9.07 dB | 0.946 |
| **严格周期成分（谐波模板）** | **14.02 dB** | **0.991** |

周期成分喂进去比**源本身**（10.72dB）还干净。结论不容含糊：
**PSOLA 的重叠相加对周期内容是干净的；沙沙来自源里的非周期成分被颗粒重排。**

两条同源机制（都随降调深度单调恶化，所以「越低声越沙」）：
1. 颗粒间距 `period/ratio`、窗半宽恒 `period` → 重叠率 `1 - 1/(2·ratio)`：
   ratio .75→33%、.62→**19%**、.50→**0%**。重叠区里相邻两颗读的是源里相隔
   `(1-ratio)·period` 的材料 → 非周期成分互不相干地叠加，再被 Σw 除法放大
   （接缝 Σw 只有 0.19 ≈ ×5 / +14dB）。
2. `advance/period = 1/ratio` 非整数（.62→1.61）→ 吸附到整数 mark 后，
   相邻颗粒的**源推进量在 1 与 2 个周期之间摆动** → 交汇相位逐颗变化 → 宽带噪声。
   `1/ratio` 恰为整数（ratio .5，−12 半音）时这一项消失 —— 这解释了为什么
   闸门修好之后 −12 特别干净。

### 实现：`hajimi_tx_run` mode 3 = PSOLA + 谐波/噪声分离

`wasm/src/psola.rs` 模块 E（`split_harmonic` / `analyse_at` / `noise_retention`）
+ `stretch.rs` 的 mode 3 分支 + 前端默认模式链 `[3, 2]`。

- 拆分：**按谐波频率做窗内正交相关**（4 个源周期的 Hann 窗），
  相位用逐样本周期积分（梯形法，与分析侧同一套插值）。
- 合成：每分析点把谐波模型**预采样成一个周期的 512 点表**，每样本只做一次
  查表 + 线性插值 —— 省掉「每样本 × 每谐波」的递推和全部三角函数。
  mode 3 ≈ 0.92× mode 1 的耗时（不是瓶颈）。
- 残余保留量 β 按 ratio 自适应：**启用线 `0.89`（≈−2 半音）以上完全不启用**，
  0.62 → β=0.50（标定点，对齐真·PitchNet 的 HF 分档），地板 0.35。
- 增益匹配的参照物必须是**谐波成分**（残余还没加回来），否则会把「噪声被抽掉」
  误当电平损失补回来、净化量被抵消。

实测（`_probe-hnsep.mjs`，mode1 → mode3，HF 分档相对源 dB = 2-4k/4-8k/8-16k）：

| 素材 | HNR 源 | mode1 | mode3 | mode1 分档 | mode3 分档 | 质心比 |
|---|---|---|---|---|---|---|
| 龙.001 @−8.23 | 10.72 | 9.07 | **10.06** | +1.3/+0.6/+0.5 | **+0.4/−0.4/−0.5** | 0.995→**0.930** |
| 高北 @−12 | 4.97 | 1.41 | **5.75** | +0.2/+0.1/+0.5 | **−0.6/−0.8/−1.6** | 0.981→**0.914** |

**mode 3 的四档全部压到源以下**，真·PitchNet 导出是 −2.0/−3.3/−2.8 —— 落到同一区间。

### 两个踩过的坑（都写进技能了）

1. **拆分不能用「±K 个周期的同步平均」**。13 抽头均匀平均的频响是 Dirichlet 核，
   f0 差 1% 时**第 10 次谐波只剩 3.6%** → 漏出来的谐波混进残余、又**不跟着变调**，
   回加后与主路打架。实测那一版比不做拆分还差：v2 7.74 vs 原 PSOLA 9.07（−1.33dB）。
   换成按谐波频率的正交相关 + 全局累积相位后，残余 RMS 占比 0.42 → 0.32。
2. **推断「沙沙」不能只看 HNR，要看频谱分档**。HNR 是标量，看不出方向；
   真·PitchNet 导出对照揭示的是**我们的输出比源还亮**（质心 1556 vs 源 1430 vs PN 983、
   >4k 占比 8.7% vs 6.5% vs 3.8%）——「在加噪声」而不是「在还原」。这才指对了方向。

### 顺带查到的成本事实（与本次改动无关）

wasm 里 mode 1 本身就是 **约 3× 实时**（0.53s 素材 217ms、0.72s 素材 260ms）。
瓶颈几乎全在 `track_pitch`（YIN）而不是合成。mode 3 只多 0.92×，可忽略。
若将来嫌慢，优化目标应该是 YIN，不是颗粒编排。

### 升调侧护栏（用户原话：「我们的高音处理可能比 PitchNet 表现好」）

用户听完的反馈：「**这个结果很糟糕 噪音变成另一种形式了**」。指标全绿、耳朵不接受。

### 撤下动作

  `'stretch'` 分支从 `[2, 3]` 回到 `[2, 1]`。两处都写了「为什么撤下」的长注释。
- `src/engine/rush/transform.ts`：`transformBuffer` 的 mode 文档补上司听结论。
- `mode 3` 的 Rust 实现与 `_probe-hnsep.mjs` **保留**（继续做实验用），
  但默认链路不再经过它，`isPsolaSilentNoop` 对它的支持也保留。

### 为什么「指标变干净」和「耳朵变难听」能同时成立

1. **HNR 这类指标对"净化"的奖励是单调的** —— 纯正弦 HNR = +∞。
   拿它当目标函数，最优点就是「把人声做成合成器」。指标只能**排除**坏方案，
   不能**选优**。这是我这次最该记的教训。
2. 抽掉的「非周期成分」其实是**气声、辅音、微抖动** —— 让人声像人声的部分。
3. 剩下的严格周期谐波在颗粒重排下变成**机械的嗡嗡/金属声**。这不是新造出来的失真，
   是 TD-PSOLA 固有的 **buzzyness**，只是原先被源里的气声**掩盖**着，抽走气声就露出来了。
4. 残余只加回一半（β=0.5）且加在**原位频谱**上，而谐波已下移 8 个半音 ——
   两层不再属于同一个声音，噪声成了「浮在低音上面的一层」。

### 顺手否掉的一个自己的假设（测量做的）

我原本猜「残余里混着没吃干净的原音高谐波，加回去会跟变调后的谐波打拍」。
探针加了 `coherentAt(x, f0, sr)`（指定 f0 上的相干能量占比）实测：

| 对象 | 相干占比 |
|---|---|
| 源 @源 f0 420Hz | 0.410（参照） |
| **残余 noise @源 f0 420Hz** | **0.072** ← 很低，假设不成立 |
| 残余 noise @输出 f0 261Hz | 0.117 |
| mode1 输出 @输出 f0 | 0.198 |
| mode3 输出 @输出 f0 | 0.180 |

残余确实是**宽带噪声**（相干占比 0.07 对 源的 0.41），不是锁在原音高上的谐波残留。
所以「打拍/不相谐部分音」这条不成立，真正的原因是上面第 2~4 条。
**测量把假设否掉，比留着它去写文档有价值。**

### 另一个顺手抓到的真 bug：启用线常量精度（已修）

`hajimi_tx_run` 的 pitch 是 **f32**，`HN_ENABLE_MAX_RATIO` 原来写 `f64 = 0.89`。
`0.89f32 = 0.88999998569… < 0.89f64` → 恰好传 0.89 的那档会 `pitch < 线` 成立，
**分离提前一个 ULP 打开**，「启用线及以上逐样本相同」这条契约在 0.89 上失效
（探针实测差异 0.61×源RMS，最大偏差落在中段 = 系统性而非边缘毛刺）。

- 修法：常量改 `f32`，`noise_retention(ratio: f32)`，比较留在 f32；
  调用点抽成 `hn_split_enabled(pitch: f32)` 以便测边界。
- 新增回归 `enable_line_is_exact_in_f32_abi_precision`：断言 `f32(0.89) == 常量`、
  且 `!hn_split_enabled(f32(0.89))`。`harmonic_mode_leaves_upshift_bit_exact` 也把
  `HN_ENABLE_MAX_RATIO` 列进「必须逐样本相同」的一侧。
- **为什么以前是绿的**：host 单测用 f64 字面量比较，永远测不到 ABI 的 f32 截断。
  这个坑只有走 wasm 的探针能看见 —— 所以探针里也钉了一段【契约】。

- `scripts/_probe-hnsep.mjs`：
  - 新增【契约】段：mode 3 vs mode 1 在 `1.0 / +5 / +7 / +12 / 0.89` 上必须逐样本相同，

### 调研结论：下一步该往哪走（纯 DSP 路线）

找成熟实现后明确了：**在 PSOLA 上做「全带波形相减 + 残余原样加回」这条路本身就不成熟**。
成熟做法是**按频带估非周期性**，合成时用谱包络**重新生成**噪声（WORLD / D4C）：

- **WORLD**（mmorise/World，BSD、无专利）：F0(DIO/Harvest) + 谱包络(CheapTrick) +
  **频带非周期性(D4C)**；周期性包络 `α²·P_x`、非周期包络 `(1−α²)·P_x`。
  噪声是**被谱包络滤出来的**，因此天然跟着音高一起走 —— 正是我们缺的那一环。
  已知坑也和我们撞上的一样：V/UV 边界 + 齿音会把噪声误判成谐波 →
  「密集的全带齿音气流重合成后变成**刺耳的脉冲串**」。
- **Praat**：PSOLA 的教科书写法（pitch mark + 局部周期 2~4 倍窗长，50%~75% 重叠）。
- **PyTSMod**：可读的 `tdpsola` / `hptsm` / `wsola` / `pv`，做 A/B 最省事。
- **Autotalent / TalentedHack**：现成的开源 **修音** 插件，PSOLA 系。
- **sannawag/TD-PSOLA**：README 自己写明「<700 音分才基本无 artifact，位移越大越差，只对 voiced 成立」。
- **Rubber Band (R3)** / **signalsmith-stretch**：现代高质量对照。
- 失真研究：Longster 2003（Bournemouth）与 SBrT'05 —— artifact 名字就叫 **buzzyness**；
  且「非周期段做 TSM 会给噪声引入周期性 → 金属声」。

## 续三：TD-PSOLA / WORLD 选型的**决策依据**（用户要求「动手之前先聊」，只调研未改码）

用户提问三件：① 我只要一个高性能、能离线部署、**不要太大**的静态网页程序；
② WORLD 系的体积到底多大、对网页有没有影响，没影响可以单开分支；
③ 他查到 PSOLA 有「改良算法 TD-PSOLA」—— 动手前先聊，用了能改善音质吗。

### 结论 1：TD-PSOLA 不是可选项，我们跑的就是它

`TD` = time-domain（对立面 FD-PSOLA / LP-PSOLA）。逐条比对 `psola.rs`：pitch mark 检测 +
互相关精修、Hann 颗粒长度恒 2 个**分析**周期、以源 mark 为锚、以新间距排放、Σw 归一
—— 这五条就是 Moulines & Charpentier 的教科书 TD-PSOLA。
网上所谓「改良 TD-PSOLA」改的是**参数与阶段划分**，不是换了一个算法。

### 结论 2：真实根因可以收敛到**一个几何量** `A = 1/ratio`

这轮把上一轮的「两个机制」合并了（旧记录里「Σw 除法把噪声放大 ×5」**不准确**）：
除法对信噪比中性；真实机制是**相干抵消打在谐波上**，而不相干叠加的噪声只按 √ 衰减。

- 重叠占比 `1 − 1/(2A)`；接缝 `Σw = 1 + cos(πA/2)`（`A=1.5→0.293`、`A=2→0`，
  与 `psola.rs` 注释那个台阶逐字对上）；接缝**相干增益** `|cos(π·frac(A))|`
  （`A=1.5 → 0` 完全抵消 = −7.02 半音那个台阶的成因；`A=1.6129 → 0.35`；`A=1 → 1`）
- 三者叠加 → 接缝**局部 SNR 下陷、以颗粒率（=输出音高）AM** → 沙沙/嗡嗡。
  −12 时没有重叠 = 一串孤立 Hann 包夹静音。
- **全部恶化来自 `A ≠ 1`**，而 `A = 1/ratio` 只是因为**单段式让颗粒几何承担变调**。

### 结论 3：两段式 = 根因的正解，且内核一行不用改

`apply_planar(x, sr, pitch=1, time = time*pitch)` + `resample(1/pitch)`。
时间伸缩阶段颗粒间距恒 = 分析周期 → `A ≡ 1`、重叠恒 50%、`Σw ≡ 1`，三条恶化同时消失。
`wasm/src/` 里目前**没有任何重采样器**（`grep resample|sinc` 为空）→ 唯一要新写的部分。
**代价**：重采样把共振峰一起搬走（×ratio）—— 这是真正的决策点，已如实告知用户。

### 结论 4：体积（用户的核心约束，实测）

|---|---|
| `public/hajimi_audio.wasm` | 1142 KB raw / **483 KB gzip** / 379 KB brotli |
| `wasm/src/` 自有源码 | ≈161 KB / 4387 行（`psola.rs` 97KB/2311 行最大） |
| `public/` 合计 | 4.77 MB，其中 **`public/_ab/` 44 个试听 WAV = 2.78 MB** |
| WORLD 全量（估，未实测） | **+130~280 KB gzip** |

## 续四：用户判定「两段式成本太高」，并问「这是不是算法问题」——**两段式撤回**

用户原话：「新方案的成本太高了 我对 TD PSOLA 算法不熟悉 这是不是算法问题」。

### 撤回两段式（已写进 MEMORY.md，防止以后重复提）

我给的两段式方案，真正的代价**不是工时**（重采样器约 100~150 行，内核一行不改），
而是**音色**：重采样把共振峰一起搬走（×ratio），降调会变成「另一个人」。
而用户觉得 PitchNet「干净又舒服」的**根本原因就是共振峰不动**（声码器 mel 不变、只换 F0）
—— 两段式恰好丢掉这一条。**拿一个缺陷换另一个缺陷，不是净改善 → 撤回。**

### 回答「是不是算法问题」：是，但要分两层（这轮想清楚的关键）

**类别上限（改不掉）**：TD-PSOLA 搬的是**源的真实波形颗粒**。
降调 = 把颗粒贴得更疏 → 接缝多；而且源的毛刺/气声**会被一起贴进去**。
神经声码器是**照（mel, F0）重新生成**波形，源颗粒根本进不去 —— 这是类别差，不是端口 bug。
文献把 TD-PSOLA 的舒适区定在 **<700 音分**，我们出问题的档是 800~1200 音分，本来就在区外。

**类内可改（有上限）**：`A = 1/ratio` 那套几何（重叠 / Σw / 接缝相干增益）确实可以整体消掉，
但消掉它就得付共振峰的代价（见上）。类内**唯一**还有文献支撑、且不动音色的是
**pitch mark 换成 epoch/GCI 检测**（文献排第一的成因是 incorrect pitch marking），
但收益有上限、可能是个 wash，风险与 mode 3 同类。

### 零成本的处置办法（推荐先给这个，而不是改算法）

用已有实测数据给**产品级档位边界**。`_probe-hnr.mjs` 的 PSOLA vs 纯重采样差
（同一输出音高，偏置相同，可比）：

| 半音 | −1.8 | −5.6 | −8.2 | −9.1 | −12.0 |
|---|---|---|---|---|---|
| PSOLA − 重采样 | **+0.99** | −2.63 | −3.95 | −6.15 | **−9.75** |

→ **拐点约在 −5 半音**：比这浅 PSOLA 反而比重采样干净；比这深单调变差。
所以「成本最低的处置」是**在界面上给降调设一个档位提示/边界**，而不是改算法 ——
不改一行 DSP 代码，也不需要用户理解 PSOLA。
